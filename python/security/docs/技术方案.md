# OSS 安全工具 - 技术文档

## 项目概述

将 OSS 安全测试工具集成到博客系统，作为博客功能的一部分。

## 架构设计

```
前端 (Next.js) ←→ Java 后端 (Spring Boot) ←→ MySQL
                    ↑
                    └──→ Python 后端 (FastAPI) ←→ SSE 实时推送
```

### 服务职责

| 服务 | 职责 |
|------|------|
| **Next.js** | 前端界面、API 路由转发、实时 SSE 连接 |
| **Java (Spring Boot)** | 用户认证、JWT 颁发、数据库管理、业务逻辑 |
| **Python (FastAPI)** | OSS 扫描核心逻辑、SSE 实时推送、结果处理 |
| **MySQL** | 博客数据 + 工具日志数据 |

### 数据流向

```
1. 登录流程：
   前端 → Java /api/auth/login → 返回 JWT

2. 工具请求流程：
   前端 → Next.js API → Python /api/oss/scan
   Header: Authorization: Bearer <JWT>

3. JWT 验证流程：
   Python 接收请求 → 解析 JWT → 验证签名 → 获取 user_id

4. SSE 实时结果：
   Python 扫描中 → 实时推送进度 → 前端展示

5. 日志记录流程：
   Python 完成/失败 → 写入 MySQL logs 表
```

## 数据库设计

### 1. 用户表 (已有)

```sql

SELECT id, username, role FROM users;
```

### 2. OSS 扫描日志表

```sql
CREATE TABLE oss_scan_logs (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL COMMENT '用户ID',
    tool_type VARCHAR(50) NOT NULL COMMENT '工具类型: bucket_fuzz/path_fuzz/perm_check/ak_leak/takeover',
    scan_mode VARCHAR(20) NOT NULL COMMENT '扫描模式: single/batch',
    target VARCHAR(255) NOT NULL COMMENT '扫描目标(Bucket名称或URL)',
    region VARCHAR(50) NOT NULL COMMENT '阿里云区域',
    options JSON COMMENT '扫描选项(字典、范围等)',
    status VARCHAR(20) NOT NULL DEFAULT 'running' COMMENT '状态: running/completed/failed',
    total_tasks INT DEFAULT 0 COMMENT '总任务数',
    completed_tasks INT DEFAULT 0 COMMENT '已完成任务数',
    results JSON COMMENT '扫描结果(JSON数组)',
    error_message TEXT COMMENT '错误信息',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    finished_at DATETIME COMMENT '完成时间',
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### 3. 安全工具使用统计表

```sql
CREATE TABLE security_tool_stats (

    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
```

## API 设计

### 1. Python 后端 API

#### 基础信息
- Base URL: `http://localhost:8000/api`
- 认证：JWT Bearer Token
- 所有请求需要 `Authorization: Bearer <token>` 头

#### 1.1 扫描任务接口

**POST /api/oss/scan**

创建扫描任务，返回 task_id

```json
// Request
{
    "tool_type": "bucket_fuzz",    // bucket_fuzz | path_fuzz | perm_check | ak_leak | takeover
    "target": "haobachang",        // Bucket名称或完整URL
    "region": "oss-cn-chengdu",     // 区域
    "options": {
        "pattern": "haobachang{i}x{j}x001",  // 可选：爆破模式
        "range": [1, 999],           // 可选：数字范围
        "wordlist": ["flag", "secret", "backup"],  // 可选：字典
        "extensions": [".txt", ".php"]  // 可选：扩展名
    }
}

// Response
{
    "task_id": "abc123",
    "status": "running"
}
```

#### 1.2 SSE 实时结果

**GET /api/oss/sse/{task_id}**

SSE 流，实时推送扫描进度

```
event: progress
data: {"progress": 10, "current": "haobachang01x0x001", "found": 0}

event: found
data: {"type": "bucket", "name": "haobachang52x8x001", "status": "exist", "url": "..."}

event: progress
data: {"progress": 50, "current": "haobachang52x8x001", "found": 3}

event: completed
data: {"total": 100, "found": 5, "results": [...]}
```

#### 1.3 查询任务状态

**GET /api/oss/status/{task_id}**

轮询方式查询任务状态（备用）

```json
{
    "task_id": "abc123",
    "status": "running",
    "progress": 45,
    "found": 2,
    "results": [...]
}
```

#### 1.4 获取历史记录

**GET /api/oss/logs**

获取当前用户的扫描历史

```
GET /api/oss/logs?page=1&limit=20

Response:
{
    "total": 100,
    "page": 1,
    "logs": [
        {
            "id": 1,
            "tool_type": "bucket_fuzz",
            "target": "haobachang",
            "region": "oss-cn-chengdu",
            "status": "completed",
            "found_count": 5,
            "created_at": "2026-05-14 10:00:00"
        }
    ]
}
```

#### 1.5 删除记录

**DELETE /api/oss/logs/{id}**

删除指定的历史记录

## 前端页面设计

### 页面路径
```
/security/tools           # 安全工具首页
/security/tools/oss       # OSS 扫描工具
/security/tools/results   # 扫描结果历史
/security/admin/stats     # 管理后台统计
```

### 界面功能

1. **工具选择**
   - Bucket 爆破
   - 路径 Fuzz
   - 权限检测
   - AK/SK 利用
   - Bucket 接管

2. **输入区域**
   - Bucket 名称 / URL
   - 区域选择（下拉）
   - 扫描选项（字典、范围）

3. **实时显示**
   - SSE 进度条
   - 当前扫描项
   - 发现的结果（列表）
   - 完成状态

4. **历史记录**
   - 分页列表
   - 筛选（工具类型、时间）
   - 查看详情
   - 删除

## 安全考虑

### 1. JWT 验证
- Python 后端验证 JWT 签名
- 检查 token 过期时间
- 获取 user_id 用于日志

### 2. 频率限制
- 每个用户每分钟最多创建 5 个任务
- 扫描任务有最大超时时间

### 3. 权限控制
- 普通用户只能看自己的扫描记录
- 管理员可以看所有记录和统计数据
