RabbitMQ learning lab / 从零看懂

一条消息，究竟走了哪条路？

你只需要先记住一句话：Producer 发消息，Exchange 做路由，Queue 存消息，Consumer 处理消息，最后 ACK。 下面的实验会把这句话变成可以点击的流程。

01 / mental model

先把 Exchange 和 Queue 分开

很多初学者把它们混成一个东西。可以这样理解：Queue 是快递柜，Exchange 是分拣中心，Binding 是分拣规则，Routing Key 是包裹上的目的地标签。

📤Producer

产生消息的应用代码。它不直接把消息塞进 Queue，而是交给 Exchange。

🧭Exchange

路由器。它根据类型、Binding 和 Routing Key，决定消息去哪个 Queue。

📥Queue

真正保存消息的地方。消息可以在这里等待消费者处理。

👷Consumer

读取 Queue 的应用代码。处理成功后发送 ACK，RabbitMQ 才会删除消息。

🔗Binding

Exchange 和 Queue 之间的绑定关系，相当于“这个路由规则通向这个快递柜”。

🏷️Routing Key

消息携带的路由标签。direct 要求完全匹配，topic 可以使用通配符。

03 / exchange types

Exchange 不是“一个名字”，它是路由策略

名字只是标识，真正决定消息去哪的是 Exchange 的类型和 Binding。这就像同一个快递分拣中心，可以采用不同的分拣规则。

当前项目为什么用 direct？
因为目前只有一条明确的事件：visit.recorded。使用 direct 可以做到“精确、简单、不容易误投”。等事件类型变多，再考虑 topic。
04 / failure path

DLX 和 DLQ：失败消息的转运中心

DLX 是 Dead Letter Exchange，负责接收“处理失败后被拒绝”的消息；DLQ 是 Dead Letter Queue，真正存放这些消息。它们不是额外的业务功能，而是失败消息的隔离区。

QueueBuilder.durable("visit.log.write")
    .deadLetterExchange("blog.dlx")
    .deadLetterRoutingKey("visit.log.write.dead")

这里的“死信”不是必然代表代码有 bug。消息格式错误、数据库持续不可用、重试次数耗尽，都可能让消息进入 DLQ。

05 / delivery guarantees

durable、persistent、ACK 到底在保护什么？

这三个词不是同一个东西。Queue 的 durable 保护“队列定义”，Message 的 persistent 保护“消息内容”，ACK 保护“消费者是否真的处理完”。

调整开关，然后模拟一次故障。

注意：durable 和 persistent 解决“Broker 重启”；Manual ACK 解决“消费者处理到一半崩溃”。它们要配合使用才有意义。

06 / duplicate delivery

为什么重复消息不会重复写日志？

RabbitMQ 通常保证的是“至少一次投递”，所以同一条消息可能被投递两次。解决办法不是祈祷不发生，而是让消费者使用稳定的 eventId 做幂等。

  • Publisher Confirm：Broker 收到了消息，不等于消费者写完了数据库。
  • Consumer ACK：消费者处理完了，RabbitMQ 可以删除消息。
  • At-least-once：消息可能重复，所以消费者必须幂等。
  • Fail-open：当前访问日志在 RabbitMQ 故障时允许丢失，优先保证博客业务可用。
glossary

术语小抄

Exchange
分拣中心。根据路由策略把消息送到一个或多个 Queue。
Routing Key
消息上的目的地标签。
Binding
Exchange 与 Queue 之间的路由规则。
DLX
接收被拒绝、过期或超过重试次数消息的 Exchange。
DLQ
保存死信的 Queue，方便排查、告警和手动重放。
ACK
消费者告诉 Broker“我处理完了”。
Persistent Message
消息写入磁盘，Broker 重启后有机会恢复。
Idempotency
同一个事件处理多次，数据库最终只产生一次业务结果。
