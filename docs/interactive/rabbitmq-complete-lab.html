01 / mental model

六个对象，先分清楚

Producer

生成消息并交给 Exchange。

Exchange

按 Routing Key 和 Binding 做路由。

Queue

真正存放待消费消息。

Consumer

读取消息并处理业务。

ACK

处理成功后告诉 RabbitMQ 可以删除消息。

DLQ

存放重试耗尽或不可处理的消息。

本次项目的拓扑： blog.events → visit.recorded → visit.log.write。失败后走 blog.dlx → visit.log.write.dlq。

04 / manual ack

ACK 不是“消息收到了”

ACK 表示消费者已经把数据库事务处理完成。先 ACK 再写库，消费者崩溃会丢消息；先写库再 ACK，崩溃后消息会重新投递。

调整模式后模拟一次消费者崩溃。
模式崩溃后行为
手动 ACK消息未 ACK，RabbitMQ 重新投递；eventId 幂等防止重复入库。
自动 ACK消息可能已经被删除，消费者写库前崩溃会丢消息。
